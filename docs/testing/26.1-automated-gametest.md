# Rally of the Guard 1.4.0 — testes automatizados no Minecraft

Este é o primeiro filtro antes do smoke test manual. Ele usa GameTest para subir
Minecraft de verdade, em servidor e cliente, sem automação de mouse ou teclado do
computador.

## Como executar

Na raiz do projeto:

```powershell
.\gradlew.bat clean automatedSmokeTest
```

O comando gera o JAR e executa em sequência:

1. testes unitários com JUnit;
2. GameTests de servidor via `runGameTest`;
3. GameTests de interface via `runClientGameTest`.

Uma execução aprovada termina com `BUILD SUCCESSFUL`. As capturas produzidas pelo
teste de cliente ficam em `build/run/clientGameTest/screenshots`.

## Cobertura atual

| Área | Verificação automática |
|---|---|
| Move Here | A ordem é anexada e removida de uma entidade dentro do mundo; o destino é preservado. |
| Move Here — terreno | O destino exige piso sólido e dois blocos livres. |
| Defend Area | Centro, posto e raio são anexados, lidos e removidos de uma entidade dentro do mundo. |
| Dispensar | Uma rotina com rota e patrulha é suspensa uma única vez, sobrevive à troca de ordem temporária e é restaurada numa entidade real. |
| Hub de formações | A tela abre, contém os sete controles esperados e mantém todos dentro da janela em `854x480` e `320x240`. |
| Comandos rápidos | A tela abre com sete controles e expõe uma opção traduzida para cada ação cadastrada, incluindo Dispensar. |
| Livro de Comando | A tela responsiva expõe categoria de unidade, Dispensar e acesso às Rotas Nomeadas sem controles fora da janela. |
| Pelotões | A gestão responsiva expõe seleção direta de Pelotões e mantém todos os controles dentro da janela. |
| Rotas coletivas | A seleção de Rota Nomeada por escopo abre com os controles esperados e layout válido. |
| Regressões de domínio | A suíte JUnit existente cobre formações, ordens, combate, pelotões, rotas, raids, perfis, rede e persistência serializada. |

Fontes dos testes novos:

- `src/gametest/java/net/hfstack/rallyguard/gametest/RallyGuardGameTests.java`;
- `src/gametest/java/net/hfstack/rallyguard/gametest/RallyGuardClientGameTests.java`.

## O que continua manual

Ainda precisa ser observado jogando:

- clareza, conforto e fluxo da interface;
- deslocamento real de vários guardas e recuperação quando ficam presos;
- combate, fogo amigo e comportamento durante raids completas;
- sincronização com dois clientes;
- salvamento após fechar e reabrir o mundo;
- integração prolongada com Guard Villagers e os demais mods;
- todas as situações anotadas no arquivo de observações.

Portanto, rode primeiro o comando automático. Se ele passar, jogue normalmente e
registre apenas bugs, melhorias e sensações de uso em
`docs/testing/26.1-1.4.0-smoke-test-observations.md`. Não é necessário repetir
manualmente cada caso puramente técnico já coberto, salvo quando uma observação
indicar regressão.
